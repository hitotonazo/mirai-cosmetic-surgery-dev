## 1. 作品・実装方針
- 作品名：**フィオルネア美容皮膚科・美容外科（FIORNEA）**。コピー「あなたらしい美しさを、もっと未来へ。」
- ごく普通の美容医療サイトから開始し、顔診断→症例標準化→採用システム流用→シミュレーター→最終運用報告書の**一本道**。想定20〜60分。PHASE0〜3＋最終確認＋Ending。
- 組織：クリニック「フィオルネア美容皮膚科・美容外科」／AI開発企業「FIORNEA DATA SYSTEMS」。システム：`FIORNEA FACE`／`SOCIAL SCORE`／標準顔`MODEL-01`。
- 公開サイトらしい自然な信頼感を最初は保つ。初回表示から不気味な赤文字や異常装飾を出さない。
- 医療機関を装った**実際の予約送信、診断用顔写真アップロード、個人情報入力・収集は禁止**。画像／施設／患者はフィクション。偽の電話番号・実在住所を捏造しない。
- 使用する完成素材は後述の画像表・ユーザー配置資産を利用する。`truth-compare-base.png`は使用禁止。

## 3. デザインと参照サイト
- 提供された参考サイト画像は**雰囲気と配置の参照**。内容・文字・実在名称・ロゴをコピーしない。
- 通常サイト：アイボリー `#F7F4F0`、背景白 `#FFFDFC`、文字 `#423A37`、くすみピンクブラウン `#AE827D`、罫線 `#DED6D1` を基準色とする（微調整は全ページ共通変数で行う）。自然な内装写真、木目、石材、清潔感、落ち着いた余白。
- 内部資料／真相：黒に近い背景 `#111317`、暗いカード `#1B2026`、本文 `#E5E6E8`、注意色 `#C85D5D`、区切り `#3B4148`。通常サイトと明確に差別化しつつ読みやすく。
- 日本語：**Noto Serif Japanese（実装CSSでは提供・取得できる Noto Serif JP の正式font-family名を確認）**。英語：**Sorts Mill Goudy**。指定フォントが実際に読み込めたことを検証。フォントファイルを無断配布しない。
- 本文PC/SP 16pxを基本、補助文字14〜15px、**14px未満禁止**。英語ラベルだけでは重要情報を伝えず日本語併記。
- 通常コンテンツ `.l-container` max-width:1200px、文章資料 `.l-container--reading` max-width:860px、PC左右40px、SP左右20px。全幅写真のみ100%。
- セクション上下余白PC：大120／中96／小64px、SP：大72／中64／小48px。共通トークンで管理。モバイルで長すぎる空白や横スクロール禁止。
- PC目安 ≥1024px、タブレット 768〜1023px、SP ≤767px。320px以上で破綻しないこと。
- Header：ロゴクリックでTOP、通常の各必須ページへのナビゲーション、PCは追従（追従時のメニュー動作と重なりを検証）。PC右側に常時操作できる「探索リセット」。SPはハンバーガーの**隣に常時表示**（メニュー内にしまわない）。
- Footer：ロゴクリックでTOP、指定のコピーライト・フィクション表記、必要な導線。
- フッター文言：`©ぺいぽぴー` ／ `※このWebサイトの内容はフィクションであり、実在の人物・団体とは一切関係ありません。`
- ナビはページごとの状態により削除・増殖させない。内部資料は内側に戻る操作を明示し、通常サイトの大きなHeader装飾を流用しなくてもよい。ただし帰還導線は省略しない。

## 4. 共通コンポーネント
- `.c-button`（Primary / Secondary / Text）で高さ48px、SP最小タップ領域44px、角丸24px、横padding24px、本文14〜16px、hover／focus-visible統一。内部資料でも寸法は維持し色だけmodifier。
- `.c-heading`、`.c-card`、`.l-container`、`.c-site-header`、`.c-site-footer`、`.c-reset`、`.c-report-section`を共通化。
- a要素/button要素は適切に使い分け、キーボード操作、ARIA、focus、動き低減（prefers-reduced-motion）対応。
- 画像は`object-fit:cover`を基本。ただし**顔写真の目鼻口を切らない**。診断シートと症例シートは事前に個別に切り出し／指定トリミングの整合性を確認。

## 5. SCSS／JS構造
- 原則 `assets/scss/style.scss` の**単一エントリーポイント**→ `assets/css/style.css` の**単一出力**。HTMLは当該CSSを参照。共通変数／base／layout／components／pages／effectsにpartial分割。コンパイル方法を `package.json` の `build:css` と `watch:css` と README に統一記載する。
- SCSSを正とし、CSSだけ編集・SCSS未反映を禁止。CodeXが編集後に自らビルド、CSSと表示を確認する。元サイトの構造が既にある場合は互換性を優先し、変更前に差分報告。
- JSはゲーム状態・診断・症例スライダー・採用シミュレーター・UIを責務分離。ハードコードされた無関係なダミー挙動禁止。

## 6. modules・状態・debug（必須）
- **実装開始前に実際のサイトデータの `modules/` を全部読むこと**。その中の「サイトが改変されました」演出、デバッグモードを**必ず再利用**。新規の類似システムを作らない。API・初期化順序・CSS依存・発火条件・タイミングは現物を調査して確定する。
- **現段階ではmodulesフォルダ自体を未確認**。`modules` の架空関数名を前提に実装しない。発見できない・互換性がない時はそこで停止し、必要ファイル／変更案を報告。
- 状態は`localStorage`へ保存し、PHASE番号に加えて異常発見済みフラグ・最終確認完了・Ending到達を保持。キー命名とスキーマは02に定義。
- 既発見のhotspot再クリック時は演出再生なしで資料へ通常遷移。再読込・戻る／進む・別ページ遷移で二重発火させない。
- debugは既存modulesの仕様を守り、PHASE切替・フラグ・リセットを可能にする。本番の通常UIにdebugを露出しない。
- リセットは確認ダイアログ→作品状態を初期化→TOPへ戻る。無関係なサイトデータを`localStorage.clear()`で一括消去しない。

## 7. 制作・公開安全条件とCodeX独自判断禁止
- 骨子にないページ、人物名、会社・学校・病院・新聞社・駅・住所・電話番号・実在企業名を**創作しない**。施設一覧はコード＋都道府県の表記を厳守。
- 不足する実際の診療価格・ダウンタイム・住所・送信先は**創作せず、実装前に確認依頼**。価格表などには後で承認されるまで架空の実数値を入れない。
- 仕様書にない重要文言・異常・PHASE・ページの分割・タブ化・モーダル連続表示・真相説明を変更しない。
- 公開前に「フィオルネア」「FIORNEA」「FIORNEA DATA SYSTEMS」等の実在名称・商標との重複確認を依頼。フィクション表記だけで実在混同リスクが消えるとは扱わない。
- X共有は実投稿せず、共有画面を開くのみ。外部へのデータ送信・実際の採用処理は行わない。
- 参照画像・指定画像・既存modulesを見ないまま「完成」としない。仕様書外で判断が必要なら**修正前に報告**。
