# 02_game-flow.md｜PHASE進行・状態管理・演出

> **実装開始前に `00_project.md → 01_pages.md → 02_game-flow.md → 03_truth-ending-images.md` の順に4ファイルすべてを確認すること。1ファイルだけを読んで実装開始しない。**
> 本文とイベント順は修正版骨子優先。作品固有の判定・状態管理を、実プロジェクトの既存`modules`のAPIに**接続**する。既存modulesを同様機能に置き換えない。

## 1. PHASE状態定義
| 永続state | 意味 | 発生条件 |
|---|---|---|
| 0 | 初期状態・普通のクリニックサイト | 初回訪問／リセット |
| 1 | PHASE1発見済 | 初めて「選考対象外」をクリック |
| 2 | PHASE2発見済 | 初めて「MODEL-01 一致」をクリック |
| 3 | PHASE3発見済 | 初めてEXTERNAL CLIENT／HR-024カードをクリック |
| 4 | 最終確認完了（PHASE追加ではない） | 「評価結果を確定する」を実行 |
| 5 | 真相／Ending到達済 | 最終運用報告書へ正規遷移 |

`phase`は最終完了ステップ番号として扱う。表示上は「PHASE0」「PHASE1」「PHASE2」「PHASE3」「最終確認完了」「Ending」とし、最終確認・Endingを新しい重要異常として扱わない。

## 2. 永続化スキーマ（仕様上の提案。既存modulesに互換キーがあればアダプタを作る）
```js
// 唯一の作品専用localStorageキー（既存moduleの独自状態と二重管理しないよう調整）
const STORAGE_KEY = 'fiornea_arg_v1';
const initialState = {
  version: 1,
  phase: 0,
  found: { diagnosis: false, cases: false, external: false },
  simulationConfirmed: false,
  endingReached: false
};
```
- ページ遷移前に状態を原子的に確定・保存する。演出が二重起動しないよう最初のイベント発火で該当`found`をtrueへ。演出が途中中断された際も、次の訪問で資料ページへ通常遷移可能にする。
- `localStorage`アクセスが不可でも同セッション内は正常に動くフォールバックを用意（ただし永続化できない旨はQA上報告）。壊れたJSON・不正phaseは初期状態へ安全復帰。
- 診断回答や個人情報は永続化しない。あくまで作品進行フラグだけ保存。
- フラグと`phase`が矛盾した場合は安全側（正規の解放範囲）へ修復する。直接URLアクセスでフラグを自動獲得させない。

## 3. 進行イベントの唯一性
| 現在 | 重要異常が現れる箇所 | 起動操作 | 初回クリック効果 | 後の移動先 |
|---|---|---|---|---|
| PHASE0 | `ai-diagnosis.html`結果パネル | 赤い「選考対象外」 | `found.diagnosis=true`, `phase=1`→**既存modulesのサイト改変演出** | `social-score-spec.html` |
| PHASE1 | `cases.html`の**一括比較スライダー1箇所** | 右端後の「MODEL-01 一致」 | `found.cases=true`, `phase=2`→**同じ共通演出** | `treatment-validation.html` |
| PHASE2 | `ai-technology.html`説明図内カード1箇所 | `EXTERNAL CLIENT／HR-024`カード全域 | `found.external=true`, `phase=3`→**同じ共通演出** | `external-link-log.html` |
| PHASE3 | `external-link-log.html`後半 | A/B選択→「評価結果を確定する」 | `simulationConfirmed=true`, `phase=4`、学習反映表示 | **同一ページ**の真相リンクを出現 |
| 最終確認 | 同ページの真相リンク | 「全国導入計画／最終運用報告書」 | `endingReached=true`, `phase=5` | `final-report.html` |

**重要：** PHASE2スライダーは、PHASE1の「社会適合度評価仕様書」の内容を見た上で症例を調べる設計。PHASE3カードは、PHASE2資料の「AI技術への取り組み」誘導後に発見させる。過去の重要異常は残してよい。**一段階で新しく増える重要異常は必ず一つ**。

## 4. 各発生条件
### PHASE0〜1：診断
- 診断は4問、進捗演出→正常美容診断結果→**同じパネルだけ**社会適合度・選考対象外へ書換え。`found.diagnosis=false`で未発見なら、最初の実行で必ず起こる。診断をスキップして突然「選考対象外」だけを見せない。
- この書換えは**「重要異常の出現」**であり、クリック後のサイト改変演出とは異なる。サイト改変演出は「選考対象外」を**クリックした時**にのみ起動。
- クリック1回目でのみ共通modules演出→内部資料。二度目以降は同じ資料へ演出なし。

### PHASE1〜2：症例
- `found.diagnosis`で一括比較スライダーを解放。通常の症例カード5枚は常時見える。
- スライダー初期値0。5人のBefore/Afterが**1本のrange**で同期して左右比較される。0でBefore全体、100でAfter全体。途中はBefore/Afterの境界が画面内同位置をスライド（「同じ位置」比較）。
- `value===100`（タッチ・キーボード操作も含む）で「共通顔形状との一致を検出」「MODEL-01 一致」表示。画像へのクリック判定は設けない。
- 初めてクリック時のみmodules演出→資料。再訪時にslider操作は可能だが演出重複なし。

### PHASE2〜3：外部カード
- `found.cases`でAI説明図の一部を「EXTERNAL CLIENT／HR-024」カードへ変化。カードのサイズ・意味は01参照。クリック可能領域＝カードの全面（文字・余白含む）。
- 初クリックのみmodules演出→ログ。既発見後は通常遷移。

### 最終確認：採用評価シミュレーター
- `found.external`で外部連携ログが正規閲覧可能となる。
- 候補者A/Bのどちらかを必須選択し「推薦候補を選ぶ」→結果は**必ずBを採用推奨、Aを紹介対象外**。ユーザー選択の正誤を採点しない。選択によって結末は分岐しない。
- 結果の説明を読ませた後、1つの「評価結果を確定する」を使う。クリックすると保存→「評価実績を学習データへ反映しました。」→短時間「低評価対象者／提携美容医療への案内候補」→同一ページ内「全国導入計画／最終運用報告書」ボタンを解放。これらは**演出上の待ち時間であり新資料ページではない**。
- 初回確定後、再訪では確認済み状態と真相リンクがすぐ復元される。二度押しで二重学習演出・二重進行させない。

### Ending
- 正規状態`simulationConfirmed=true`のときのみ真相ページ解放。真相ページ閲覧でendingReached保存。X共有ボタンは最下部に設置。
- Ending後：進行フラグを維持してサイトを再訪可能にする（TOP/各異常も再閲覧できる）。共通modules演出を繰り返さない。唯一の全初期化手段は「探索リセット」。

## 5. 初回演出と再訪挙動
- **既存modulesの**「サイトが改変されました」演出を3箇所でのみ呼ぶ。参考骨子の「ノイズ」「ヘッダー/背景/文字の改変」「INTERNAL SYSTEM ACCESS」「DISPLAY OVERRIDE」等は既存演出の外観・文言・時間と競合する場合、勝手に改造せず実装前に確認。
- 演出実行中の連打／二重クリックは無効化。共通moduleの完了通知に従って遷移。遷移完了前に更新しても発見済み状態は維持。
- 再訪クリックは共通演出なし／資料ページへ即時または通常の画面遷移。再訪時は進行度が巻き戻らない。
- `prefers-reduced-motion`利用者には演出時間短縮等を既存module互換の範囲で対応（内容・結果は同じ）。

## 6. URL直打ち／Refresh／Back／Forward
- 未到達の内部資料（5/6/7）や真相ページ（8）の**URL直打ち**では先の情報を開示しない。解放条件がなければ、余計な専用ページを作らずTOPへ戻す（必要に応じて短い通常文言を表示）。
- `social-score-spec`は`found.diagnosis`、`treatment-validation`は`found.cases`、`external-link-log`は`found.external`、`final-report`は`simulationConfirmed`を必須条件とする。
- TOP・診断・症例・AI技術は常時アクセス可。ただし未解放の異常は見せない（診断のみ4問後に初回異常）。
- ブラウザ戻る／進む、BFCache復帰時（pageshow）には状態を再読込してUIと照合。進行フラグを履歴移動によって減らさない。
- リロード時：PHASEと発見済み情報を復元。進行途中の演出の強制再生は禁止。シミュレーター確認済みなら結果と真相導線を復元。
- URLハッシュ等をPHASEバイパスに利用しない。

## 7. Debugとリセット
- CodeXは`modules`内既存デバッグUIの起動方法と機能を読み、**その仕組みで**phase0〜3、最終確認、Endingの状態を生成・表示可能にする。debug操作でphaseを移す場合、対応する`found`フラグと整合させる。
- 通常公開UIでdebugの呼出し方法や開発情報を不用意に表示しない。
- Header探索リセットは、PCでは原則ヘッダーに常設。SPはハンバーガーのすぐ横に常設。確認ダイアログでOK時のみ**作品固有キーとmoduleの該当状態**を削除→`index.html`へ戻す。キャンセルは無操作。

## 8. テストケース（合否条件）
1. 新規状態でindexは普通の美容サイト、異常はどこにもない。
2. 4問と診断演出完了後、採用「選考対象外」が意図的に出現。6種類どれでも必ず到達可能。
3. 初回「選考対象外」クリックで1回だけサイト改変→仕様書へ遷移。戻る／再訪では再演出なし。
4. PHASE1未解放では症例の一括スライダーなし。解放後1本のスライダーで5人同時変化。
5. 100%だけ「MODEL-01 一致」出現、画像直接クリックでは進行しない。
6. 初回MODEL-01クリックで1回改変→検証記録。再訪は演出なし。
7. PHASE2未解放ではAI技術図に外部カードなし。解放後HR-024だけが重要異常として現れる。
8. HR-024カードの余白含む全面クリックで1回改変→外部連携ログ。再訪は演出なし。
9. シミュレーターAを選んでもBを選んでも判定B・A除外。結果確定をしないと真相リンクが出ない。
10. 真相直打ち未達時は非公開、解放後は入れる。リロード／Back/Forwardでフラグ整合。
11. Debugから各ステップへ移れる。resetで全初期状態、無関係localStorageは保存。
12. SP320px以上、44pxタップ領域、キーボード操作、画像の顔位置・視認性が保たれる。
